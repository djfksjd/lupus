# 전체 설계 재검수와 1.2 보완 기록

검수일: 2026-10-04. 대상: LUPUS-PLAN.md 1.1, LUPUS-ASTRA-REVIEW.md, LUPUS-PONYTAIL-ASSESSMENT.md, LUPUS-CAVEMAN-ASSESSMENT.md. 작성자 검토와 GPT-6 Astra 독립 재검수의 결과를 합쳐 정리했다. 기존 검수에서 충분히 다루지 않은 경계 변경·복구·분기·완료 기준을 중점 추적했다. 실행 시험이나 CLI 설치는 수행하지 않았다.

## 판정과 범위

조직 구조를 폐기할 문제는 없지만 기존 1.1에 중요한 누락과 표현 충돌이 있었다. 아래 항목을 계획 1.2에 반영했다. 문서 보완은 실행 가능성·안전성 시험 통과를 의미하지 않는다. 구독 인증과 격리/입력 통제의 양립은 P0.5에서 먼저 확인한다.

## 보강한 실행 기준

CONTEXT-01, REVOKE-01, RESTORE-01, ACCEPTANCE-01, INCIDENT-01, INGEST-01, BUDGET-01, WAIT-01을 본 계획의 운영 기준에 추가했다. 기존 AUTH/SEC/RECOVERY/USAGE 기준과 함께 시험한다. 테스트용 합성 비밀·자료를 사용하며 실제 고객 정보로 누출 시험을 하지 않는다.

## 여전히 실행으로 확인할 사항

- 양 CLI의 지원 버전에서 구독 인증·정제 설정·외부 격리·통제된 입력이 함께 동작하는지.
- native TUI와 엄격 입력 경로의 UX 및 강제 가능 범위.
- Agent Memory의 실제 full/fallback·데이터 위치·캡처 hooks와 삭제/복원 동작.
- supervisor가 upstream의 자식 호출·스케줄·사용량·중지를 실제로 통제할 수 있는지.
- 기존 hooks와 전역 스킬 설명 비용, RAG 품질, 전체 완료 업무당 사용량.

지원하지 않는 기능은 미지원으로 표시하고 보호 모드·자율 실행을 활성화하지 않는다. 모든 정보를 잃은 백업에서 과거 외부 상태를 확정할 수 있다고 가정하지 않는다. 외부 제공자에 이미 보낸 자료를 로컬 삭제로 회수할 수 있다고 주장하지 않는다.

## 수정본 확인

Astra가 1.2 수정본을 확인해 F01~F13 반영과 주요 계약의 일관성을 확인했다. 마지막 권고인 독립 삭제/철회 기록 소실 때 복원 자료의 검색·context 주입·export·Generated 재생성 차단을 본문에 추가했다. 이 보완을 전제로 설계 수준의 중대한 잔여 모순은 발견하지 않았다는 판정이다. P0.5 가능성 시험에 적합하며 설치·보안·성능 검증 완료를 뜻하지 않는다.
