# Caveman 점검과 간결한 보고 정책

작성일: 2026-10-04. 공개 문서와 일부 소스 점검이며 설치·프록시 실행·모델 비교 시험은 하지 않았다.

## 결론

사용자가 진행을 이해하고 결정할 수 있는 만큼만 보고하는 원칙을 채택한다. 새 스킬을 만들거나 전체 패키지를 설치하지 않고 공통 보고 정책에 반영한다. 한국어의 조사·부정·조건을 보존하며 원시인 연기를 하지 않는다.

Caveman response skill은 출력 문체 지침이다. 입력·파일·추론 토큰을 압축하지 않는다. 현재 저장소는 별도 proxy/engine/middleware도 제공하므로 문체 지침과 실행 계층을 구별한다.

## 공통 보고 계약

기본 최종 보고는 다음 항목 중 실제 필요한 것만 3~5줄로 출력한다. 짧고 명확한 한국어를 사용한다. 초기 목표는 일상 보고 200~400자이며 보안·승인·복잡한 요청·사용자가 상세 설명을 요구한 경우 초과할 수 있다.

1. 결과: 무엇이 바뀌었고 완료/진행/대기 중인지.
2. 검증: 완료 판단에 필요한 핵심 증거, 미검증 범위.
3. 문제 또는 결정: 중요한 실패·위험·차단·사용자의 선택.
4. 다음 행동: 다음 작업 또는 사용자에게 필요한 답변/승인.
5. 상세: 산출물이나 Obsidian 업무 노트 링크 하나.

예:

> 로그인 수정 완료. 만료 토큰 차단, 유효 토큰 통과 확인.
> 운영 배포는 대기. 배포 승인 필요.
> 상세: 해당 업무 노트 링크.

진행 보고는 의미 있는 단계 변경·새 문제·승인 필요 시 한두 문장으로 한다. 호스트가 요구하는 상태 알림 빈도는 지킨다. 완료를 검증하지 않았으면 완료라고 쓰지 않는다. 사용자가 작업 방식을 이해하는 데 필요한 변경 이유를 생략하지 않는다.

승인 보고에는 실행 대상·자료 범위·외부 목적지·관련 비용과 되돌림 가능성을 모두 구체적으로 포함한다. 부정·예외·수치·단위·명령을 줄여 의미를 바꾸지 않는다. 사용자 질문이나 상세 설계 요청은 그 요청에 필요한 깊이로 답한다.

## 상세 기록과 입력 절감

Obsidian에 목표·계획·담당·변경 근거·검증·다음 행동을 남긴다. 구조화된 운영 이벤트로 상태를 투영하고 기존 산출물에 링크한다. 매번 A부터 Z까지 긴 모델 보고서를 작성해 저장하는 방식은 피한다. 필요한 설명·결정만 한 번 기록하고 대화에서는 참조한다.

에이전트 간 전달은 task ID·완료 조건·허용 범위·산출물 참조·검증·차단 사유로 구조화한다. 인간용 말투를 기계 계약에 강요하지 않는다. tool output 축약은 오류·실패·보안 관련 증거를 보존하고 권한 검사 후 필요한 원문 범위를 다시 조회할 수 있어야 한다.

## 프록시 채택 조건

현재 프록시는 설치하지 않는다. 추후 채택을 검토하면 구독 인증·provider 경로, 기본 텔레메트리 비활성, 네트워크 목적지, 원문 SQLite/백업 보관·삭제·권한 전파, 오류 누락·복원 품질, 정책 중복, 전체 비용을 별도로 검증한다. 원문을 디스크에 보관하는 기능은 비밀정보 제거를 대신하지 않는다. 모델 전송 전뿐 아니라 원문 SQLite·로그·백업 저장 전에도 허용 자료 판정과 정제가 선행되어야 하며 민감정보를 배제한다. 비공식 OAuth 추출이나 구독 인증 우회는 사용하지 않는다.

## 채택 시험

간결한 기본 보고 / Caveman 원칙 반영 보고를 같은 업무에서 비교한다. 전체 출력과 지침 입력뿐 아니라 사용자의 재질문, 놓친 승인·위험, 성공률, 재작업 비용을 측정한다. 이해와 통제에 필요한 정보를 놓치거나 총사용량이 늘면 더 명확한 기본 보고로 복귀한다.

현재 코드의 라이선스는 Apache-2.0이며 이전 버전과 일부 기여의 MIT 고지도 보존한다. 실제 코드를 복사하거나 배포할 경우 해당 고지와 의존성 조건을 확인한다. [라이선스 설명](https://github.com/JuliusBrussee/caveman/blob/aeb45e2f787c0757a8af383a291a280cb6aeb4c1/LICENSING.md).

## Astra 추가 검수

추가 보고 정책은 설계로서 적합하며 현재 채택 범위에서 중대한 누락은 없다는 판정을 받았다. 권고한 저장 전 민감정보 배제도 반영했다. 실행 시험은 수행하지 않았다.
