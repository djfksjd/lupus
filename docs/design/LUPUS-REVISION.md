# Lupus 1.3 보완 기록

작성일: 2026-10-04. 기존 1.2의 보안·승인·권한 철회·복구 원칙을 유지하면서 사용자 요구를 추가했다. CLI 설치·새 스킬 생성·기존 Vault 이동은 하지 않았다.

## 사용자 요구와 반영

- 이름: Lupus. 문서 제목·제안 저장소·Vault 이름 통일. 2026-10-05 사용자 요청으로 문서 파일명을 LUPUS 기준으로 통일하고 링크를 갱신.
- 원칙: 무목적·무근거·중복·무진전 지출 허용 0. 토큰뿐 아니라 구독·시간·추가 지출·유지보수·사용자 부담 포함. 실제 실패/손실은 숨기지 않으며 완벽한 무낭비 실적을 사전 보장하지 않음.
- Goal/Ralph: 검증 → 필수 고도화 → 영향 검증 → 증거에 따른 진전 비교. 완료하면 종료하고 선택 개선은 별도 계약/예산.
- 헛돌기 방지: 입력/변경/근거 없는 재시도 차단, 가설당 초기 2회 정책, 연속 무진전 정지, 총예산과 resume 누적 횟수 유지.
- 시험 비용: 최소 유효 영향 검사부터, 조건부 증거 재사용, 필요한 최종 회귀. 권한·승인·외부 현재 상태 확인은 캐시로 대체하지 않음.
- 다른 영역: event 기반 supervisor, idle 모델 금지, 선택 분업, 필요한 RAG·선별 경험·증분 색인, 스킬 metadata cache, Prime의 실제 손실 trigger·기각·rollback, 짧은 보고와 로컬 관측.
- 도입 순서: 최소 안전·재개·메모리 운영 먼저. Ruflo/Prime/추가 플러그인은 실제 필요와 이득을 확인한 후 선택.

## Astra 검수와 추가 보완

Astra는 새 비용 원칙과 test→개선→test 흐름이 일관되며 요청 범위에서 아래 두 가지 외 중대한 새 모순을 발견하지 않았다고 판단했다.

1. 변경 전에 필수 검증·안전 종료·rollback 예산 예약. 부족하면 변경 시작 금지, 안전 예약을 다른 worker에 재배정 금지.
2. 완료 후 선택 개선은 별도 허용 예산이나 사전 배정 상위 예산 사용. 완료 목표를 다시 열거나 시도/예산 초기화 금지. 후보를 무한 생성해 상한 우회 금지.

두 지적을 계획 6·11·15에 반영했다. Astra는 문서만 검토했으며 파일 수정이나 실행 시험은 하지 않았다.

## 구현 승인 기준

LOOP-01~04와 ECONOMY-01~04를 추가했다. 위반 차단과 종료뿐 아니라 필수 조건 미달을 DONE으로 처리하지 않는지, 통과 목표를 선택 최적화 때문에 RUNNING으로 붙잡지 않는지 확인한다. 계획에 제안한 횟수/상한은 초기 정책이며 설치 때 업무 위험도와 사용자 예산에 맞춰 확정한다.
